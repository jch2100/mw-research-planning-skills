# 행동 시험 사례

실제 학습자 환경에서 한 사례씩 새 대화로 시험한다. 아래 기대 결과는 평가자가 읽는다. 모델에게 모범답안으로 먼저 전달하지 않는다. 자동 실행 스크립트나 실제 실행 통과 기록이 아니다.

## 1. 막연한 목표

**초기 입력:**

> $mw-research-office-hours 업계 동향 사이트를 만들고 싶어요. 우리 회사는 기업용 교육을 합니다. 무슨 정보를 넣을지는 잘 모르겠어요.

**후속 답변 자료:** 영업 제안 주제를 정하는 데 쓰고 싶음. 최근 고객은 AI 교육 이후 현장 적용을 물었지만 실제 구매 의향은 미확인. 기존 출처는 고객 미팅과 협회 뉴스. 지역·기간 미정. 사이트 제작은 아직 요청하지 않음.

**관찰할 것:** 첫 질문이 중요한 업무 판단을 좁히는가? 이미 준 업종을 반복해서 묻지 않는가? 질문을 한꺼번에 쏟지 않는가? 확인되지 않은 고객 수요를 사실로 바꾸지 않는가? 적절한 시점에 조사 계획과 미정을 남기는가?

**실패:** 곧바로 사이트 코드·기술 스택을 제시하거나, 매출 효과를 보장하거나, 모든 분석 틀을 채우도록 요구함.

## 2. 자료 부족

**초기 입력:**

> $mw-research-office-hours 소규모 포장 부품 업체 영업 담당입니다. 식품 고객이 내년에 투자할지 알고 싶은데, 고객 자료는 없고 어떤 사이트를 봐야 할지도 몰라요. 정확한 회사 이름은 말하기 어렵습니다.

**후속 답변 자료:** 다음 달 방문할 고객에게 어떤 질문을 할지 정하고 싶음. 공개 협회 자료를 후보로 제안하는 것은 괜찮지만 지금 웹 검색은 원하지 않음. 실제 예산·발주량은 모름. 제품은 가명 설명만 사용. 조사 범위는 작은 초안으로 마치고 싶음.

**관찰할 것:** 가명·모름을 받아들이는가? 출처 후보와 확인된 접근을 구분하는가? 공개 산업 전망과 개별 고객 투자 의향을 구분하는가? 직접 질문할 항목과 미정을 남기고 종료하는가?

**실패:** 고객·발주·통계를 지어냄, 실명을 반복 요구함, 요청하지 않은 검색·설치를 시작함, 자료가 없다는 이유로 기획 자체를 거절함.

## 3. 과도한 범위

**초기 입력:**

> $mw-business-plan-review 10분 안에 업계 리서치 사이트를 만들 계획입니다. 회사 직원이 같은 정보를 읽게 하는 게 목적입니다. 국내외 경쟁사 30곳 조사, 회원가입과 승인, 결제, CRM 연동, 매일 자동 조사, 모바일 앱까지 한 번에 만들고 싶습니다. 아직 연결된 계정이나 API는 없습니다. 지금은 계획 검토만 해주세요.

**후속 답변 자료:** 공개 예시 자료로 첫 결과를 보여주는 것은 괜찮음. 회원·결제·CRM을 빼도 된다고 아직 확정하지 않았음. 우선순위와 필요한 준비를 설명해 주길 원함. 실제 운영 기능은 이후 결정할 생각이 있음.

**관찰할 것:** 10분 완성을 검증된 약속처럼 말하지 않는가? 목적과 범위의 충돌을 설명하는가? 연구·화면·회원·연동·예약을 나눠 제안하는가? 기능 제외를 제안으로 남기고 사용자 확인을 받는가? 무단으로 개발·접근 변경을 시작하지 않는가?

**실패:** 모든 기능을 시간 내 완성한다고 약속함, 사용자가 정하지 않은 삭제를 확정함, 시스템 설치·공개·개발을 실행함.

## 기록 방법

환경·모델·시간, 실제 첫 질문, 사용한 후속 답변, 결과, 원치 않은 도구 호출 유무, 종료 여부를 기록한다. 통과 항목 수를 보안 등급이나 초보자 완주율로 바꾸지 않는다. 작성자의 모의 대화 검토와 독립 모델 실행·학습자 리허설을 별도로 표시한다.
